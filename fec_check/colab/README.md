# Colab GPU 실행 패키지

- `fec_colab.ipynb`: Colab에서 위에서부터 실행하면 됩니다. 시뮬레이터 코드가 노트북 안에 들어 있어 저장소 접근이 필요 없습니다.
- `fec_gpu.py`: 시뮬레이터 본체입니다. GPU에서는 CuPy, CPU에서는 numpy로 돕니다. 노트북을 바꾼 뒤에는 `python3 make_notebook.py`로 다시 생성합니다.
- `python3 fec_gpu.py selftest`: 같은 오류 패턴에 대해 CPU 기준값과 비트 단위로 일치하는지 확인합니다.

## 구현 검증 (CPU)

- **제품부호 복호기:** `pcode.py`와 같은 오류 행렬 192프레임에서 결과가 완전히 일치했습니다(p = 0.009, 0.011, 0.012).
- **Staircase 생략 최적화:** 바뀐 블록이 없는 그룹은 다시 복호하지 않도록 했습니다. 최적화 전 코드와 결과가 완전히 일치했습니다.

## Staircase 예비 결과 (CPU, W = 7, v_max = 10)

| p | 복호기 | 블록 수 | 실제 블록 오류 | 실제 BER | 기준(genie) 오류 |
|---|---|---|---|---|---|
| 5.5×10⁻³ | 논문 문구 | 2,560 | 1,337–1,773 | 7–9×10⁻⁴ | 0 |
| 5.25×10⁻³ | 논문 문구 | 1,920 | 85 | 3.0×10⁻⁵ | 0 |
| 5.25×10⁻³ | lock_first | 1,920 | 21 | 1.2×10⁻⁵ | 0 |
| 5.25×10⁻³ | 논문 문구, W = 10 | 1,920 | 17 | 1.0×10⁻⁵ | 0 |
| 5×10⁻³ | 논문 문구 | 38,400 | 9 (잔여 무게 1–3) | 8.4×10⁻⁹ | 0 |
| 5×10⁻³ | lock_first | 38,400 | 1 (잔여 무게 2) | 8×10⁻¹⁰ | 0 |

- 기준 복호기의 워터폴은 p ≈ 6.5×10⁻³ 근처입니다. 실제 복호기는 그보다 낮은 약 5.3×10⁻³에서 워터폴을 지납니다.
- **논문 문구 그대로의 일정**에서는 출력 직전 블록의 행 성분이 다시 복호되지 않습니다. 이 때문에 무게 1–3짜리 잔여 오류가 남습니다.
- **lock_first 일정**은 직전 출력 블록과 창 첫 블록이 이루는 행 성분을 다시 복호하되, 출력 블록 자체는 고치지 않습니다. 이 설정에서 p = 5×10⁻³의 BER은 8×10⁻¹⁰(사건 1회)입니다. 논문의 약 2×10⁻¹⁰과 같은 자릿수이지만, 사건이 1회뿐이라 신뢰구간이 넓습니다.
- 따라서 Colab 본 실행에서는 lock_first를 주 설정으로 씁니다.
